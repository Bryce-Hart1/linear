# linear: plan and outline

## Context

drawBridge (`~/Desktop/CSCI/git/drawBridge`) has a keyboard-first `.lin` diagram editor in
Svelte/TS under Tauri. Its format and behaviour are pinned down in `lin_summary.md`, with
about 2,000 lines of logic and 2,500 lines of tests in `app/src/lib/lin/`. **linear** is a new,
standalone editor in `~/Developer/linear` (currently an empty folder, not yet a git repo) that:

- edits three document kinds: **`.lin` diagrams** (strict v1, byte-identical with drawBridge),
  **`.lpx` pixel art** (layers + indexed palette) and **`.ldw` drawings** (vector pen strokes);
- has a clean, **clickable** UI (tool rail, inspector, menus, context menus), with keyboard
  shortcuts as accelerators rather than the only way in;
- is a Rust/Tauri app whose backend uses **Diesel + SQLite** to store the documents
  (with version history) and the user's preferences.

Decisions made with the user: Tauri + Svelte; pixel art v1 = layers + palette (no animation);
drawings = vector strokes; `.lin` = strict v1.

**Where the logic lives.** All editing, geometry, rendering and file parsing/serialising stays in
TypeScript, so it never needs a round trip through IPC per mouse move, and the `.lin` modules are
reused unchanged. Rust owns storage (Diesel), the file system (import/export by path), the native
menu, the window, and the `thumb://` protocol. Content crosses IPC only on open, save, draft and
export.

**Document-kind registry** (`kinds.ts`). Library, New, import, save, export and thumbnails are written
once against this interface:

```ts
interface DocKind<D> {
  kind: 'lin' | 'lpx' | 'ldw'; ext: string; label: string; icon: Component;
  blank(opts?): D;
  parse(text: string): D;              // throws "item 3: …" style errors
  serialize(doc: D): string;
  thumbnail(doc: D, side: number): Promise<Uint8Array | null>;
  exports: ('png' | 'jpeg' | 'svg')[];
  Editor: Component;                   // gets a DocSession<D>
}
```

## 2. Storage (Diesel + SQLite)

The database lives at `app_data_dir()/linear.db`. It uses an r2d2 pool of 4 connections, and each
connection is set up with `PRAGMA journal_mode=WAL`, `foreign_keys=ON` and `busy_timeout=5000`.
Migrations are embedded (`embed_migrations!`) and run at startup. Every command is `async` and runs
its Diesel work in `spawn_blocking`. Times are unix milliseconds in `BIGINT`.

```sql
CREATE TABLE folders (
  id INTEGER PRIMARY KEY, parent_id INTEGER REFERENCES folders(id) ON DELETE CASCADE,
  name TEXT NOT NULL, created_at BIGINT NOT NULL);

CREATE TABLE documents (
  id INTEGER PRIMARY KEY, folder_id INTEGER REFERENCES folders(id) ON DELETE SET NULL,
  name TEXT NOT NULL,                          -- without extension
  kind TEXT NOT NULL CHECK (kind IN ('lin','lpx','ldw')),
  thumbnail BLOB,                              -- small JPEG; NULL when empty
  pinned BOOLEAN NOT NULL DEFAULT 0,
  created_at BIGINT NOT NULL, updated_at BIGINT NOT NULL, opened_at BIGINT,
  trashed_at BIGINT);                          -- NULL = not in Trash

CREATE TABLE versions (                         -- append-only; newest id = current content
  id INTEGER PRIMARY KEY,
  document_id INTEGER NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
  content TEXT NOT NULL, bytes INTEGER NOT NULL, created_at BIGINT NOT NULL);
CREATE INDEX versions_by_doc ON versions(document_id, id DESC);

CREATE TABLE drafts (                           -- crash recovery for unsaved work
  document_id INTEGER PRIMARY KEY REFERENCES documents(id) ON DELETE CASCADE,
  base_version_id INTEGER NOT NULL, content TEXT NOT NULL, updated_at BIGINT NOT NULL);

CREATE TABLE prefs (key TEXT PRIMARY KEY, value TEXT NOT NULL);   -- JSON values

CREATE TABLE palettes (id INTEGER PRIMARY KEY, name TEXT NOT NULL,
  colors TEXT NOT NULL, created_at BIGINT NOT NULL);              -- JSON ["#rrggbbaa", …]
```

Rules, enforced in `linear-store` and covered by its tests:

- **Create** inserts a document and its first version (the blank serialised content) in one
  transaction. Folder names and document names must be unique within their parent folder, checked
  in code (SQLite's UNIQUE treats NULL parents as distinct, so it can't enforce this at the top level).
- **Save** appends a version, updates `updated_at` and `thumbnail`, deletes the draft, and prunes
  to the newest `versions.keep` versions, all in one transaction. Saving content identical to the
  head version returns "no changes" (the drawBridge behaviour).
- **Restore a version** appends a copy of it as a new version, so history is never rewritten.
- **Trash** sets `trashed_at`. "Empty Trash" deletes permanently, and the UI confirms it first.
- **Prefs** have a typed `Prefs` struct in Rust with serde defaults. `get_prefs` merges the stored
  rows over the defaults. `set_pref(key, json)` is rejected unless the merged result still
  deserialises, so unknown keys and wrong types fail.

Prefs v1: `theme` (system/light/dark) · `library.view`, `library.sort`, `library.kind` ·
`ui.sidebarWidth`, `ui.inspectorOpen`, `ui.showHints` · `window.bounds` (restored at startup by
Rust) · `versions.keep` (50) · `draft.delayMs` (2000) · `lin.openIn` (view/edit), `lin.playOnOpen`,
`lin.grid` · `lpx.defaultSize` (32×32), `lpx.defaultPalette`, `lpx.showGrid`, `lpx.exportScale`
(8) · `ldw.page` (1600×1000), `ldw.pen` {color, width, opacity}, `ldw.smoothing` ·
`export.lastDir`.

## 3. IPC commands (`src-tauri/src/commands.rs`)

| Area | Commands |
|---|---|
| Library | `list_documents {folder?, kind?, query?, view: all\|recent\|pinned\|trash}`, `list_folders`, `create_folder`, `rename_folder`, `move_folder`, `delete_folder` |
| Documents | `create_document {name, kind, folder?, content}`, `open_document(id) → {meta, content, draft?}`, `save_document {id, content, thumbnail} → {version} \| "no changes"`, `rename_document`, `move_document`, `duplicate_document`, `set_pinned`, `trash_document`, `restore_document`, `empty_trash` |
| Versions | `list_versions(id)`, `read_version(vid)`, `restore_version(vid)` |
| Drafts | `put_draft {id, base_version_id, content}`, `discard_draft(id)` |
| Prefs and palettes | `get_prefs`, `set_pref`, `list_palettes`, `save_palette`, `delete_palette` |
| Files | `read_import(path) → {name, ext, text}` (capped at 1 MiB for `.lin` and 16 MiB otherwise), `write_export {path, bytes}` |

The `thumb://localhost/<docId>?v=<updated_at>` protocol serves `documents.thumbnail` for the
library's `<img>` tags; the drawBridge `thumbs.rs` and CSP pattern carry over. **Import** goes:
dialog or Finder drop → `read_import` → TS `parse` (the real validator, so errors read
"item 3: …") → `create_document`. **Export** goes: save dialog (the extension picks the format) →
TS renders the bytes → `write_export`. Exporting as `.lin`, `.lpx` or `.ldw` writes the serialised
text exactly.

## 4. Formats

### 4.1 `.lin`: strict v1 port
- Copy `drawBridge/app/src/lib/lin/{model,format,geometry,text,edit,keys,pulse,snap,clip,draw,svg}.ts`
  and every `*.test.ts` into `app/src/lib/lin/` **unchanged**. Only the editor component's edges
  (save, export, thumbnails) are rewritten against linear's session and API.
- Golden fixture: serialise drawBridge's `SAMPLE_DIAGRAM` (`app/src/lib/mock.ts`) to
  `app/src/lib/lin/fixtures/flow.lin`. The test asserts `serializeLin(parseLin(f)) === f`.
- Everything the new clickable UI adds must go through existing `edit.ts` functions, or produce
  only states v1 can already express. No new fields.

### 4.2 `.lpx`: pixel art v1 (new)
```json
{"lpx":1,"w":32,"h":32,"next":3,"pal":["#00000000","#1a1c2cff","#5d275dff"],"layers":[
 {"id":1,"name":"Background","show":true,"lock":false,"op":100,"px":"<base64>"},
 {"id":2,"name":"Ink","show":true,"lock":false,"op":100,"px":"<base64>"}
]}
```
- `w`, `h` are 1–512. `pal` holds 1–256 colours as `#rrggbbaa`, and index 0 is always transparent
  (forced on read). `layers` run bottom to top, 1–16 of them, each with an `id` that is unique and ≥ 1.
- `px` is base64(deflate-raw(`w·h` bytes of palette indices, row-major)), using fflate so it is
  synchronous and deterministic. An index ≥ `pal.length` is an error.
- Like `.lin`, it is written one part per line, strict about structure and forgiving about numbers
  (`op` is clamped to 0–100). Errors name the part ("layer 2: …"). Unknown fields are ignored.
- In memory, each layer is a `Uint8Array` of indices plus a cached RGBA `ImageData`, which is rebuilt
  for the dirty rectangle after each edit, or entirely when the palette changes.

### 4.3 `.ldw`: drawing v1 (new)
```json
{"ldw":1,"w":1600,"h":1000,"bg":"#ffffff","next":3,"items":[
 {"id":1,"t":"pen","c":"#111111","w":3,"o":100,"pts":[120.5,88,121,90.5]},
 {"id":2,"t":"hl","c":"#f7c948","w":16,"o":35,"z":true,"pts":[]}
]}
```
- `w`, `h` are 200–8000, and `bg` is `#rrggbb` or `"none"` (a transparent export).
- `t` is `pen` or `hl` (highlighter). `c` is `#rrggbb`, `w` is 0.5–64, `o` is opacity 1–100,
  `z` (closed path) is optional, and `pts` is a flat array of x,y pairs rounded to a tenth.
- One stroke per line, back to front. Defaults are omitted and the reading rules match `.lin`.
- One function turns points into a path (quadratic curves through midpoints, round caps and
  joins). Canvas, SVG and PNG export all use it, so they match.

## 5. UI design (clean and clickable)

**Shell.** The window uses an overlay title bar (as drawBridge does).
- **Sidebar**, collapsible and resizable:
  - a **New ▾** button (Diagram / Pixel art / Drawing) and a search field;
  - Recent, Pinned, All, the folder tree (drag documents onto it; right-click for New folder, Rename, Delete), and Trash;
  - a Settings gear at the bottom.
- **Library**:
  - a grid of thumbnail cards (name, kind icon, "edited 2h ago"), or a list;
  - kind filter chips and a sort menu;
  - an empty state with three large "New …" buttons;
  - a card context menu: Open, Rename, Duplicate, Move to…, Pin, Export file…, Move to Trash;
  - files dropped from Finder are imported.
- **New dialog**: the kind, a name, and the size (pixel presets 16/32/64/128/256 or custom; drawing page size) and palette.

**EditorFrame** (shared by all three editors):
- **Top bar**: ← Library · an editable title · ● unsaved · Undo/Redo · zoom (− 100% + · Fit) ·
  kind-specific actions · **Export ▾** (PNG/JPEG/SVG/native file) · **⋯** (Versions…, Duplicate,
  Move to Trash).
- **Left tool rail**: icon buttons with tooltips that name the shortcut ("Rectangle · R").
- **Right inspector** (toggled): the selection's properties as swatches, segmented controls and number fields.
- **Bottom status bar**: the status/description, error notes (`{error}` results from edits), and an
  optional key-hint row.
- **Right-click context menu** on the canvas, mirroring the keyboard. **⌘/** opens a shortcut sheet.
- A **draft recovery banner** appears when a draft newer than the head version exists: Keep / Discard.

**Native menu** (`menu.rs`):
- **App**: About, Settings ⌘,, Quit.
- **File**: New Diagram ⌘N, New Pixel Art, New Drawing, Import… ⌘O, Save ⌘S, Export… ⌘E, Close ⌘W.
- **Edit**: Undo/Redo as custom items; Cut/Copy/Paste/Select All as *predefined* items, so text
  fields keep native behaviour and the canvases handle the DOM `copy`/`cut`/`paste` events;
  Duplicate ⌘D; Delete.
- **View**: Zoom ⌘= ⌘- ⌘0, Sidebar, Inspector, Theme ▸.
- **Help**: Shortcuts ⌘/.

Menu items emit a `menu` event, and `menu-router.ts` sends it to the focused text field
(`execCommand`) or to the active editor. Single-letter shortcuts stay in canvas keydown handlers,
which ignore keys while an `<input>` has focus.

### 5.1 `.lin` editor
- All of drawBridge's behaviour, including View/Edit/Typing modes and the full key map.
- **Rail**: Select, Circle, Triangle, Rectangle, Diamond, Line, Hand. Choosing one arms the tool,
  exactly like `c`/`t`/`r`/`d`/`l`.
- **Shape inspector**:
  - colour swatches 0–9, font S/M/L, and outline solid/dash/dot;
  - W/H fields that keep the 24–800 range and refuse sizes too small for the text;
  - an "Edit text" button, with B/I/U buttons while typing;
  - arrange buttons ([ ] { }).
- **Line inspector**:
  - arrowheads none/end/both, Flip, route, pulse off/→/←/↔, and ball/light;
  - colour, outline, and the label with its font.
- **Multi-select**: the properties the selection shares.
- **Mouse additions** (each maps to existing edit functions):
  - 8 resize handles: dragging anchors the opposite edge, and ⌥ resizes around the centre; circles stay round;
  - connector dots on a hovered shape: drag one out to make a line, which attaches on drop;
  - double-click a shape or line to type into it;
  - a Play/Pause and View/Edit toggle in the top bar.

### 5.2 Pixel editor
- **Tools**:
  - Pencil (B), Eraser (E), Fill (G: contiguous or global), Line (L, Bresenham);
  - Rectangle (R) and Ellipse (O), outline or filled, with ⇧ to constrain;
  - Eyedropper (I, or ⌥-click), Select (M) with a floating selection and cut/copy/paste, Move (V), and Hand (H or space).
- **Options bar**: brush size 1–8 (square or round), mirror X/Y, pixel-perfect stroke.
- **Colour panel**: primary and secondary swatches (X swaps them; left/right click paints).
  - The palette grid: click picks, double-click edits, and a + button adds a colour.
  - Palette menu: built-in presets (16-colour default, greyscale, 1-bit), or save/load a palette in the library (`palettes` table).
- **Layers panel**: thumbnail, name, show, lock, opacity; add, duplicate, delete, merge down; drag to reorder.
- **Canvas**:
  - a checkerboard for transparency, integer zoom 1–64×, and a pixel grid from 8×;
  - a brush-footprint cursor and marching ants around selections.
- **Image menu** (⋯): Canvas size… (with an anchor), Flip H/V, Rotate 90°.
- **Undo** stores dirty-rectangle patches (layer, rect, before and after bytes) instead of
  whole-document snapshots, so 200 steps on 16 × 512² layers stays small. Layer and palette edits
  are their own small commands. The document is "modified" when the history position differs
  from the saved position.
- **Export**: a flattened PNG at an integer scale of 1–32× (nearest neighbour), transparent or on a colour.

### 5.3 Drawing editor
- **Tools**: Pen (P), Highlighter (H), Eraser (E: removes each stroke it touches), Lasso (S),
  Line (L), Rectangle (R), Ellipse (O), and Hand (space).
  - Shapes become strokes; rectangles and ellipses set `z`.
- **Options**: colour (the 10 `.lin` colours, a custom picker, and recent colours), width presets
  1/2/4/8/16/32, opacity, and smoothing.
- **Input pipeline**: pointer events → a lazy-brush stabiliser (the strength comes from the smoothing
  setting) → live preview → when the stroke ends, Ramer–Douglas–Peucker simplification (0.5 px) →
  points rounded to a tenth.
- **Selection** (lasso or click): move, delete, recolour, change width or opacity, front/back,
  copy/paste, duplicate.
- **Undo**: whole-document snapshots, 200 deep. Strokes are immutable, so snapshots share them.
- **Export**: PNG or JPEG (2×, cropped to the content plus 32 px, or the whole page) and SVG.

- **The real app**: `npm --prefix app run tauri dev`. Create one document of each kind, then:
  - save, quit and reopen, and check that everything persists;
  - kill the app mid-edit and check that the draft banner appears;

- **Cross-app `.lin` check**: export a `.lin` from linear, open it in drawBridge, save it there, and
  re-import it. The text must be byte-identical.

## 8. Risks and notes
- **Menu accelerators against the WKWebView keydown.** The M0 spike settles this before any editor
  depends on it. As a fallback, leave ⌘ shortcuts off the menu items and handle them in keydown, as
  drawBridge does today.
- **`.lpx` size**: a worst case of 16 × 512² is about 4 MiB raw before deflate, which is acceptable
  in SQLite. The 16 MiB import cap covers it.
- The `.lin` modules are copied, not shared, with drawBridge. Fixes need porting in both directions;
  extracting a shared npm package can come later if that becomes painful.
